# 마스킹 규칙

RCA 리포트를 저장하기 직전에 적용한다. 기준 사례: `docs/rca/a-connection-pool.md`.

## 적용 시점

- 수집 · 타임라인 · 발췌 단계에서는 원문 값을 그대로 다룬다. 학생 식별자도 줄이지 않는다(`STU-…` 로 미리 가리지 않는다). 같은 학생인지 끝까지 구분할 수 있어야 하기 때문이다.
- 리포트를 저장하기 직전, 마스킹 단계에서 아래 규칙을 리포트 전체(본문 · 표 · 발췌 · 실행 명령 · 명령 출력)에 한 번에 적용한다.

## 유형별 규칙

| 유형 | 규칙 | 예 |
|---|---|---|
| IP | 앞 두 옥텟만 남기고 나머지를 `x` 로 바꾼다. | `10.20.3.11` → `10.20.x.x` |
| IP(구분 필요) | 서로 구분해야 하는 주소는 역할 별칭으로 바꾼다. 리포트 앞부분에 별칭과 역할을 한 번 적는다. 단말처럼 같은 역할이 여럿이면 사고 구간 등장 순서대로 A, B, C … 를 붙인다. | `API-1`, `API-2`, `교사단말A` … |
| IP 축약 · 꼬리 표기 | 축약 표기(`3.11`)와 꼬리 표기(`.21`)도 같은 주소의 전체 표기와 같은 별칭으로 바꾼다. | `.21` → `API-1` |
| 이메일 | 아이디를 `***` 로 바꾸고 도메인은 남긴다. | `kim@school.example` → `***@school.example` |
| 학생 식별자 | 등장 순서대로 `학생A`, `학생B` … 로 바꾼다. 같은 학생은 리포트 끝까지 같은 별칭을 쓴다. | `STU-10234` → `학생A` |
| 토큰 · 세션 ID · API 키 · `Authorization` 값 | `[TOKEN]` | `Authorization: Bearer [TOKEN]` |
| 비밀번호 · 접속 문자열 | `[SECRET]` | `-p[SECRET]`, 접속 문자열 전체 → `[SECRET]` |

## 가리지 않는 것

- `127.0.0.1` 등 루프백 주소. 리포트에는 `localhost` 로 표기한다.

## 대응표 · 원본 취급

- 원래 값 ↔ 별칭 대응표를 파일로 남기지 않는다(리포트 · 임시 파일 · 메모 모두).
- 마스킹 전 원본을 임시 폴더(스크래치패드 · `/tmp` 포함)에 복사하지 않는다. 원본은 `incident-logs/` 에서 읽기만 한다.

## 적용 기록

리포트 맨 끝에 유형별 건수를 한 줄로 적는다. 0건인 유형도 적는다.

```
마스킹 적용: IP 별칭 N건(전체 주소 N · 축약 표기 N · 꼬리 N) · IP 부분 가림 N건 · 이메일 N건 · 학생 식별자 N건 · 토큰 N건 · 비밀번호 N건
```
