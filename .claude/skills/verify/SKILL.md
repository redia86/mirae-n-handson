# 변경분 검증

검증 대상: $ARGUMENTS

- 인자가 비어 있으면 `git diff upstream/main...HEAD` 를 대상으로 삼는다.
- 이 Skill 은 리뷰 쪽 역할이다. 대조 · 실행 · 판정만 하고 보고한다.

## 절차

### 1. 요청 범위 확인
- 무엇을 요청했는지 한 문장으로 확인한다.
- 요청 범위가 주어지지 않았으면 판정하지 말고 먼저 질문한다. 범위를 모르는 채로 "요청 범위 이탈 없음"을 판정하지 않는다.

### 2. 변경 파일 목록과 diff 읽기
- `git diff --stat <대상>` 으로 변경 파일 목록을 먼저 본다. patch 파일이면 `git apply --stat <파일>` 로 목록을 뽑는다.
- 파일마다 diff 를 읽는다.

### 3. 체크리스트 대조
- 직접 하지 않고 reviewer Sub-agent 에 위임한다. 비교 범위(검증 대상 diff 범위 또는 patch 파일)와 1단계에서 확인한 요청 범위 문장을 그대로 넘긴다.
- reviewer 에게 아래 기준으로 대조해 이슈 목록을 돌려받는다.
- 저장소 루트의 `templates/approval-checklist.md` 를 읽는다. 항목을 이 파일에 옮겨 적지 않고 매번 그 파일을 기준으로 본다.
- 항목마다 충족 · 미충족 · 확인 필요 중 하나로 표시한다.
- 심각도(치명 · 경고 · 제안) 정의도 같은 파일을 따른다.
- 컨벤션은 저장소 루트의 `CLAUDE.md` 코딩 컨벤션 · 금지 사항과 대조한다.

### 4. 테스트 실행
- 직접 하지 않고 tester Sub-agent 에 위임한다. 변경 파일 목록과 요청 범위를 넘긴다.
- 새 로직(새 public 메서드 · 엔드포인트 · 쿼리)에 테스트가 없으면 tester 가 테스트 파일을 추가하게 하고, 실행 결과(통과 · 실패 수, 실패한 테스트 이름, 추가한 테스트 파일 목록)를 돌려받는다.
- tester 에게 아래 기준으로 실행하게 한다.

변경 파일 목록에 나온 폴더의 테스트만 실행한다.

| 변경된 곳 | 실행 명령 |
|---|---|
| `modern/api/` | `cd modern/api && ./gradlew test` |
| `modern/web/` | `cd modern/web && npm test` |
| 이관 코드 | `cd characterization && npm test` (레거시 대상)<br>`cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test` (새 API 대상) |

- 출력은 통과 · 실패 수와 실패한 테스트 이름만 남긴다. 전체 로그를 대화에 싣지 않는다(필요하면 `tail` · `grep` 으로 요약 줄만 본다).
- characterization 은 실행 전에 대상 서버가 떠 있는지 확인한다(레거시 · 새 API `http://localhost:8080`). 새 API 가 꺼져 있으면 실행하지 말고 사람에게 기동을 요청한다.
- 서버가 꺼져 있거나 의존성이 설치되지 않아 실행할 수 없으면 그 사실을 적고 사람에게 기동을 요청한다. 그 기준은 "미충족"으로 판정한다.

### 5. 승인 기준 판정
- reviewer · tester 의 보고를 모두 받은 뒤 메인 세션이 네 기준을 최종 판정한다. Sub-agent 의 판정을 그대로 옮기지 않는다.
- 두 보고가 엇갈리면 엇갈린 지점(어느 기준, 각자의 근거)을 그대로 적고, 판정하지 말고 사람에게 묻는다.
- 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 판정한다.
- 네 기준이 모두 충족이면 승인, 하나라도 미충족이면 반려다.
- 이슈가 0건이면 경고 · 제안 수준까지 한 번 더 본다.

reviewer 또는 tester Sub-agent 가 없는 환경에서는 3 · 4단계를 기존 방식대로 메인 세션이 직접 수행한다.

## 출력 형식

```
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령과 통과 · 실패 수, 실패한 테스트 이름 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 이슈 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |
|---|---|---|---|---|

확인 필요
- (근거 줄번호를 댈 수 없는 지적)
```

- 이슈 한 건은 심각도(치명 / 경고 / 제안) · `파일:줄번호` · 근거 · 수정 방향 순서로 네 항목을 모두 채운다.

## 하지 말 것
- 코드를 수정하지 않는다(tester 가 추가하는 테스트 파일은 예외). 보고만 한다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"로 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
