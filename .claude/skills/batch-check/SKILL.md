# 배치 점검

로그 폴더: `$ARGUMENTS`. 비어 있으면 `pipeline-samples/batch-logs` 를 쓴다.
건수 파일은 로그 폴더의 상위 폴더에 있는 `datamart-counts.csv` 를 쓴다.

## 1. 날짜 기준부터 맞춘다
- 로그 파일 이름 · 로그 줄의 `date=` · 줄 시각, CSV 의 `date` · `loaded_at` 을 비교해 각 날짜가 실행일인지 기준일인지 확인한다.
- 관계를 한 줄로 밝히고(예: "둘 다 기준일, 실행은 다음날 새벽") 같은 날짜 기준으로 맞춰 대조한다.

## 2. 점검 기준 (job × 날짜마다)
1. 실행 여부: 다른 날에는 매일 돌던 job 이 그날 없거나, START 만 있고 같은 run_id 의 SUCCESS 가 없으면 이상.
2. 중복 실행: 같은 날 같은 job 의 SUCCESS 가 2회 이상이면 이상.
3. 적재 건수: 직전 7일 평균에서 ±30% 를 넘게 벗어나면 이상. 0건은 무조건 이상.
   - 평균에서 해당 날짜는 빼고, 이미 이상으로 판정된 값도 뺀다.
   - 앞선 기록이 7일 미만이면 있는 날만 쓰고 "n일 평균"이라고 표시한다. 앞선 기록이 없으면 "판정 제외"로 둔다.
4. 지연: 소요 시간이 평소 소요 시간의 2배를 넘으면 이상.
   - 평소 소요 시간 = 그 job 의 이상이 아닌 날 소요 시간의 중앙값.
   - 소요 시간은 SUCCESS 줄의 `elapsed=` 를 쓰고, 없으면 START · SUCCESS 시각 차이로 구한다.

## 3. 작업 규칙
- 로그를 통째로 읽지 않는다. `grep -n` · `awk` · `wc -l` 로 필요한 줄만 뽑는다.
- 평균 · 중앙값 · 편차는 암산하지 않는다. 명령이나 스크립트(스크래치패드에 둔다)로 계산한다.
- 근거는 로그면 `파일:줄번호`, 건수면 `CSV n행` + 해당 행 값으로 적는다.
- 로그에 없는 원인은 추측하지 않는다. 원인은 "확인 필요"로 두고, 무엇을 더 봐야 하는지만 적는다.

## 4. 리포트
- 이상이 한 건도 없으면 파일을 만들지 않고 "이상 없음" 한 줄로만 답한다.
- 이상이 있으면 `docs/batch-check/report.md` 에 저장한다.
  1. 맨 위 요약 한 줄: 점검 기간, 이상 N건. 건수는 (날짜, job, 점검 항목) 단위로 센다.
  2. 날짜 관계 한 줄, 계산 방법(평균 일수 · job 별 평소 소요 시간).
  3. 이상 목록 표: 날짜 | job | 점검 항목 | 근거 | 영향 추정 | 다음 확인 사항
     - 영향 추정에는 로그 · CSV 에 보이는 사실만 적는다.
  4. 맨 아래: "이상 없음으로 판정한 날짜" 목록. 판정 제외 항목이 있으면 함께 적는다.
- 저장 직전에 `.claude/skills/rca/masking-rules.md` 의 규칙(IP · 이메일 · 학생 식별자 · 토큰 등)을 리포트 전체에 적용하고, 맨 끝에 마스킹 적용 기록 줄을 넣는다.
- 저장한 뒤 `grep` 으로 원래 IP · 이메일 · `STU-` 가 남지 않았는지 확인한다.
- 답변에는 이상 건수, 파일 경로, 마스킹 건수만 적는다.
